# 设计说明

## 要解决的问题

用 AI 讨论社会议题和人生问题时，常见的三种失效模式：

1. **通顺但无用**：答案结构完整、语言漂亮，但读完判断没有变化，也无法验证任何一条
2. **迎合**：顺着提问者的情绪和立场放大结论，把安慰当分析，把立场当事实
3. **过载**：一次性铺开大量信息与视角，看似全面，实际什么都没记住，也没形成判断

本仓库的提示词针对这三点设计，核心手段是**约束 AI 的输出形式**，而不是要求它"更深刻、更全面"——后者几乎无效。

## 六条设计原则

### 1. 强制分类，而不是强制篇幅

要求每条结论标注【事实】/【推论】/【价值】。这一条约束的作用最大：它让"看起来像事实的观点"暴露出来，也让对话双方知道分歧究竟在事实层还是价值层。

### 2. 用可检验性替代可信度声明

不说"请确保信息准确"，而是要求：来源分级、附原文片段、交叉验证、标注"未找到证据"。凡是无法落到可核查来源的结论，形式上就写不出来。

### 3. 把反方写成最强版本

要求重建对立立场到其支持者认可的程度，再说明分歧性质（数据 / 方法 / 价值）。这比"列出不同观点"更难被敷衍，也更能暴露自己的偏误。

### 4. 深度分档与时间盒

L1/L2/L3 三档，每档规定时间与输出物。防止把所有问题都推成学术研究，也防止重要问题只停在情绪层面。到点无法判断时，允许的输出是"证据不足，需要 X"。

### 5. 把自我判断拆成可验证命题

人生类问题最容易卡在模糊的自我评价上（"我能力不够""来不及了"）。提示词要求把这类句子改写成：命题 → 需要的证据 → 什么会推翻它 → 2–4 周可完成的最小实验。同时区分可逆与不可逆决策，后者要求更长观察期。

### 6. 明确禁止清单

禁止套话、鸡汤、伪精确、编造来源、"这取决于你"式收尾、和稀泥结论。禁止清单比正面要求更容易执行，也更容易事后检查。

## 结构选择：为什么是总控 + 模块

- **总控**负责路由、深度分档、通用输出规范（事实/推论/价值、禁止项、收尾格式）。它解决的问题是"无论问什么，基本纪律都在"。
- **模块**负责各自的专业结构：社会议题需要因果层次与利益结构；人生问题需要约束条件与实验设计；知识补课需要地图与边界；需要外部事实时先取证再分析。
- **双轨**意味着两套都要能用：单轮问答可以直接粘贴模块；长期使用则挂总控，让它自动判断走哪条线。两者内容有少量重叠（输出规范），修改时需要同步——这是这套结构的已知成本。

## 语言层面的具体设计

- 用**不可执行的指令**做防呆："不要写'综上所述'"这个要求可检查；"请深刻"不可检查
- 用**格式约束**代替态度要求：要求填表（利益相关方表、证据表、命题表），填不满就会暴露信息不足
- 用**收尾动作**强制收敛：每轮必须以"我可能错在哪 + 三个追问 + 只有我能决定的事 + 可迁移框架"结束，避免对话以感想收场
- 保留**边界声明**：专业领域（医疗、法律、财务、工程安全）明确标注需要持证专业人士判断

## 已知局限

- 提示词无法阻止模型编造来源，只能通过"要求原文片段 + 要求写未核实"降低概率；**关键事实仍需人工抽查**
- 长提示词会挤占上下文，长对话中出现约束衰减（后半段不再遵守分档与禁止项）；建议每 5–8 轮重新粘贴总控
- 结构化输出有固化风险：框架用久了会变成填空题，答案趋于同质。缓解办法是定期回看洞察卡片，检查是否真的产生了不同的判断
- 面向中文语境写作，方法论条目以中文可得的资料为主

## 迭代方式

**先取证，再改条款。** 想系统性升级时，先跑 `prompts/50-design-research.md`（元层检索），拿到“方法 → 证据强度 → 可写条款”的映射，再决定加什么、删什么；不要凭感觉往提示词里堆条款。

- 修改**纪律类**内容（分类、禁止项、收尾格式）→ 改 `prompts/00-master.md`，并同步各模块的收尾段
- 修改**领域结构**（分层、维度、表格）→ 只改对应模块
- 修改**参考材料**（方法论、证据标准、追问清单）→ 改 `docs/`，不影响提示词本体
- 每次改动后用一个真实问题跑一遍：如果输出变长了但判断没变，这次改动就是无效的
- 证据被推翻或新综述出现时，回到对应条款修订，并在 `docs/design-notes.md` 记录改动理由
